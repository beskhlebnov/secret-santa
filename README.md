# Тайный Санта — GitHub Pages + Supabase

Статический сайт с аккаунтами, группами, пожеланиями, тайной жеребьёвкой, ограничениями для пар участников и генератором подарков. Серверная часть и база — Supabase; фронтенд — GitHub Pages.

## 1. Создать Supabase

1. Откройте https://supabase.com/ и создайте бесплатный проект.
2. В проекте перейдите **SQL Editor → New query**.
3. Откройте файл `supabase/schema.sql`, скопируйте весь текст и запустите (`Run`).
4. Откройте **Project Settings → API** (или API Keys в новом интерфейсе) и скопируйте:
   - Project URL;
   - anon / publishable key. **Не используйте service_role key в браузере.**
5. Откройте `js/config.js`, замените заглушки:
   ```js
   window.SUPABASE_URL = 'https://ВАШ_ПРОЕКТ.supabase.co';
   window.SUPABASE_ANON_KEY = 'ВАШ_ПУБЛИЧНЫЙ_ANON_ИЛИ_PUBLISHABLE_KEY';
   ```
   Публичный anon/publishable key допустим на клиенте при корректных RLS-политиках. Секретный service_role key никогда не вставлять в сайт.
6. В Supabase **Authentication → URL Configuration** добавьте адрес сайта в Site URL и Redirect URLs, например:
   `https://ВАШ_GITHUB_NICK.github.io/secret-santa/`
7. Для удобства можно выключить подтверждение email (Authentication → Providers → Email → Confirm email). Если оставить включенным, участникам нужно подтверждать email, прежде чем войти.

## 2. Публикация на GitHub Pages

1. Создайте GitHub repository с названием `secret-santa`.
2. Загрузите содержимое этой папки в корень репозитория (именно файлы `index.html`, `css/`, `js/`, `supabase/`, `README.md`, а не дополнительную вложенную папку).
3. В репозитории зайдите **Settings → Pages**.
4. В разделе Build and deployment выберите **Deploy from a branch**.
5. Branch: `main`, Folder: `/ (root)`, нажмите Save.
6. Подождите публикации. Адрес будет `https://ВАШ_GITHUB_NICK.github.io/secret-santa/`.
7. Убедитесь, что URL сайта добавлен в Supabase Auth URL Configuration.

## 3. Использование

- Создатель регистрируется / входит, создаёт игру и получает код.
- Отправляет код участникам.
- Участники регистрируются, вводят код и имя, затем заполняют желания.
- Организатор может до жеребьёвки добавить ограничения «участник A не дарит участнику B». При необходимости добавьте встречное ограничение тоже.
- После проверки списка и ограничений организатор нажимает «Провести жеребьёвку». Результат фиксируется, повторно запустить нельзя.
- Каждый участник видит только своего получателя и его пожелания. Пожелания видны их автору и назначенному дарителю.
- Генератор идей подарков работает в браузере и не требует базы.

## 4. Ограничения / заметки

- Это MVP для небольших групп, не коммерческий сервис.
- Жеребьёвка выполняется серверной RPC-функцией, а доступ к данным контролируется RLS.
- Исключения задаются направленно: A → B означает, что A не может дарить B. Чтобы исключить взаимный обмен, добавьте B → A.
- Если много исключений, может не существовать подходящей жеребьёвки. Тогда удалите часть ограничений и повторите до запуска.
- После запуска результат нельзя изменить через интерфейс. Если нужно отменить игру, создайте новую.
- Пользователь с доступом к GitHub репозиторию может менять сайт. Не помещайте в репозиторий пароли или ключ `service_role`.
- В MVP организатор не имеет доступа ко всем пожеланиям участников — пожелания открываются только автору и назначенному дарителю.

## 5. Если сайт не работает

- Если сообщение говорит, что нужно указать Supabase — проверьте `js/config.js`.
- Если регистрации/входа не получается — проверьте Authentication → Providers → Email и настройки подтверждения email.
- Если вход прошёл, но RPC сообщает ошибку — проверьте, что `schema.sql` выполнен целиком.
- Если GitHub Pages не обновился — Settings → Pages проверьте источник и статус workflow; обновление иногда занимает несколько минут.
